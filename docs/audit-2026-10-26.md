## 3. Accepted limitations (unchanged, documented)

1. **Tracker cap is not strictly enforceable** (AUDIT-10-04). Rules cannot count
   documents; a strict cap needs a trusted server, which needs Blaze. What is
   guaranteed: a tracking day never references more than 8 trackers, every
   over-cap write fails closed with a clean domain error, and nothing is
   partially written. Recovery = delete one tracker.
2. **Option A vs Option B accounting** (AUDIT-10-07). Multi-entry dates can
   over-credit "saved". Activating Option B stays blocked on the product decision
   in `docs/financial-semantics.md` §17.
3. **Owner-forgeable aggregates.** A LEGACY owner can misstate their own
   `lifetimeAggregates` with a rules-valid direct write. Accepted for a
   self-tracking app; cross-user isolation and shape bounds still hold. App Check
   would not change this (and is no longer used at all).
4. **No App Check / no attestation** (AUDIT-10-08). Abuse resistance for the
   public API key rests on Google Cloud API-key restrictions, not on app
   attestation. If App Check enforcement is ever enabled in the Console while
   clients do not request tokens, every request is rejected — see
   `SETUP_GUIDE.md` → "App Check (not used in this project)". Two inert SDK-level
   hooks remain and cannot be removed without excluding Firebase internals:
   `firebase-appcheck-interop` on the Android classpath (transitive of the
   Firestore/Functions SDK) and the vendor chunk's `settings.appCheckToken`
   check on web. Neither activates without a registered provider.
5. **Android does not reject invalid counts, it filters them.** `InputSanitizer`
   now matches the web filter exactly, but the Android UI cannot produce a
   fractional/invalid count (integer taps only), so no user-visible difference.
6. **Dead reference code.** `webApp/src/services/dailyLedger.js` and
   `functions/` remain in the repo as undeployed reference (BACKLOG W1B-4b), and
   are not a production dependency.
7. **Comment-only drift in `firestore.rules`.** Its header still describes the
   retired "App Check integrated but not enforced" arrangement. The file was
   deliberately left byte-identical (rules changes require independently proven
   defects); the authoritative statements live in `SECURITY.md` and
   `SETUP_GUIDE.md`.
8. **Persisted-record compatibility of `validateCounts`** (AUDIT-10-02). Every
   count written under the current rules is a whole number in `[0, 10000]`, and
   a stored integral double (e.g. Android's `3.0`) reads back in JS as the integer
   `3`, so `createManualEntry`/`updateHistoricalDay`/`updateHistoricalLog`/
   `restoreLog` accept all conforming records unchanged. The only value that can
   now be *rejected* where it was previously *attempted* is a stored fractional
   count (possible only if a much older rules version allowed it); that write was
   already denied by the rules, so the change turns an opaque permission error
   into `INVALID_COUNT` copy. No stored document is read differently or
   rewritten.

## 8. Instrumentation result gate — replaced with a real XML parser

Up to and including §7 the gate extracted counts with `grep`/`awk` over the JUnit
XML. That is fail-closed for the cases it tested, but it never *parses* the
document: a truncated or hand-edited file with a plausible-looking
`<testsuite tests="28" failures="0">` opening tag would satisfy it, and attribute
extraction cannot notice a structural lie (declared totals that do not match the
`<testcase>` elements actually present).

The gate is now `.github/scripts/android-test-results-gate.py` (stdlib
`xml.etree.ElementTree` only — no new dependency), invoked by
`.github/workflows/android-integration.yml`, and covered by
`.github/scripts/test-android-test-results-gate.py` (26 tests, run in CI before
the emulator boots). It fails closed on:

| Condition | Code |
|---|---|
| results directory missing | `NO_RESULTS_DIR` |
| no `*.xml` under it | `NO_RESULTS` |
| every file predates the run marker | `NO_FRESH_RESULTS` |
| marker missing (freshness unprovable) | `MISSING_MARKER` |
| XML is not well-formed (truncated/corrupt) | `MALFORMED_XML` |
