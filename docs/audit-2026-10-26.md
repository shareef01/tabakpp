# Repository audit — 2026-10-26 (branch `audit/2026-10-26-hardening`)

Scope: full-stack inspection of the Web PWA and the Kotlin/Android clients,
Firestore Security Rules, the Spark cost profile, offline/reliability
behaviour, account deletion/export, and cross-platform parity. Findings below
are only those with a located file, function and reproducible scenario. Every
fix has a regression test that failed before it.

**Nothing was deployed, migrated or activated.** Firebase stays on Spark, no
Cloud Functions are deployed or depended on, App Check enforcement is untouched
(and remains off), no production record was rewritten. Option B remains parked
(`docs/release-hardening/RELEASE_GATES.md`).

Baseline on the branch point (branch `26;10;26`, `76c293a`): `lint` clean,
vitest **461**, rules/emulator **126**, contract **66**, `:shared:test` and
`:composeApp:testDebugUnitTest` green — so each defect below was reproduced
against a *green* baseline, not against accumulated breakage.

## 3. Accepted limitations (unchanged, documented)

1. **Tracker cap is not strictly enforceable** (AUDIT-10-04). Rules cannot count
   documents; a strict cap needs a trusted server, which needs Blaze. What is
   guaranteed: a tracking day never references more than 8 trackers, every
   over-cap write fails closed with a clean domain error, and nothing is
   partially written. Recovery = delete one tracker.
2. **Option A vs Option B accounting** (AUDIT-10-07). Multi-entry dates can
   over-credit "saved". Activating Option B stays blocked on the product decision
   in `docs/financial-semantics.md` §17.
3. **Owner-forgeable aggregates.** A LEGACY owner can misstate their own
   `lifetimeAggregates` with a rules-valid direct write. Accepted for a
   self-tracking app; cross-user isolation and shape bounds still hold. App Check
   enforcement would not change this and remains off.
4. **Android does not reject invalid counts, it filters them.** `InputSanitizer`
   now matches the web filter exactly, but the Android UI cannot produce a
   fractional/invalid count (integer taps only), so no user-visible difference.
5. **Dead reference code.** `webApp/src/services/dailyLedger.js` and
   `functions/` remain in the repo as undeployed reference (BACKLOG W1B-4b), and
   are not a production dependency.
